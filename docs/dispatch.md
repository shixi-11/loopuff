# 星港调度

四项挑战将课程中的条件、循环、函数与消息用于变化的输入。一份源码必须处理当前任务的全部批次；单个样例正确不能完成任务。新轮次更新调度数据，保留玩家代码和已有徽章。

## 输入契约

- `branch`：星港提供 `cargo` 与 `threshold`，检查0至9的载重。小于阈值输出1，否则输出2。玩家编写完整的条件程序。
- `manifest`：提供 `docks` 与 `offset`，包含空清单、重复编号、不同长度与顺序。按清单逐项加上偏移后输出。空清单只检查正常运行且没有输出，方法要求在其他非空批次中检查。
- `fuel`：玩家定义 `fuel`，接受两个参数并返回其和。星港追加调用并显示返回值，检查载重0至9、储备量2至5的40种组合。输入值只通过函数参数进入玩家定义，参数名可自定；调用接口的函数名固定。
- `relay`：星港创建 `west` 与 `east` 通道，在独立并行分支发送两份报告。玩家只能通过接收取得报告数值；另提供 `threshold` 与 `reserve`。检查两边各0至6的49种组合。收到的两个值经函数合计，大于阈值时加储备量，再输出结果。

最后两项有明确的调用与消息边界，避免用无效函数或空消息装饰全局数值计算。前后缀是游戏输入设施，未增加Tolang语法。原生语义由独立编译器样例对照；浏览器执行仍使用项目的受限学习模型。

每批通过实际执行和贡献来源评分。总任务要求所有批次完成且通过；还有接收在等待时，已有部分正确输出也不能完成任务。每条所需输出都必须包含任务要求的方法贡献，不能借旁边一条正确计算为固定答案背书。预览按所选批次展示输入、实际输出、需要的信号及输出所对应的源码。宿主追加的调用保留真实源码，不标成玩家编辑器里的区间。[排查反馈](dispatch-repair.md)会定位当前批次的边界、等待或具体输出，并能打开该值的执行记录。

## 状态与保存

独立键为 `loopuff-dispatch-v1`。保存种子、所选任务、四份草稿、与当前草稿一致的提交、当前轮已完成任务、累计任务徽章及完成轮数。运行结果、表格、动画、查看的批次和键盘焦点不持久化，恢复时重新执行一致的提交。

编辑使当前结果失效，不删除历史徽章。任务切换、语言切换和页面刷新保留代码。新轮保留草稿、徽章与累计轮数，清空当前轮的提交和完成标记；四项首次全部完成时计一轮，重复提交不再计数。完成标志从四项完成事实恢复，缺少旧标志不能重复计轮。

源码最多3000字符，为星港输入与调用后缀预留运行器空间。其他资源边界沿用学习运行器。读写存储失败时可继续当前页面，并提示复制代码；记录可以通过进度与备份页手动备份、恢复或与账号存档合并，登录本身不自动替换本机进度。本地记录不作为可信排行榜或能力认证。

旧课程、追逐与保险库的存档键、规则和奖励保持独立。徽章与完成轮数只描述这组挑战，不改变既有探索积分。
