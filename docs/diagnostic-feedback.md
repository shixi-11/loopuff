# 让诊断指出下一步

问题：诊断补学始终选领域列表第一课（名字与计算会回到最初的输出课）；刷新后复检没有选择失败输入；已通过程序仍摊开完整提示。上一版已在提交时自动选择首个失败输入，本次保留该行为，不重复实现。

决定：从本次真实报告推导反馈、具体补学课程和一组可查看的失败输入；空白、执行错误、等待、调用机制、缺失的数据贡献、边界输入与普通输出不符分开。只描述当前程序和输入，不诊断人的总体能力。对同一概念的不同合理解保持有效。多输出诊断逐条检查概念贡献，复用改写题的检查逻辑，原课程评分契约不变。

提示按当前程序的报告收起：通过后已看过的提示可重新展开，旧hint计数不清零；编辑或换组取消通过状态，提示不会插入代码。检查未通过时补学只给具体下一步，不跳回整个课程开头。通过者可直接继续其他诊断/独立任务。

状态：不改任何持久化版本或字段。报告仍重新执行得出。当前查看的case和提示展开仅保存在页面model，按seed与领域隔离，回到诊断时保留；刷新后重新复检并定位首个失败输入。切课不修改诊断草稿、输入seed、提交或旧成绩；换组明确清除旧报告和查看位置。

边界：不根据错误猜测未执行的概念；执行失败时不把blocked项当缺失技能。边界提示只陈述实际输入特征，不声称已经找出根因。不增加自动通过、课程解锁、排名或掌握称号，不增加导航入口，不更改追逐或银行机制。

验证：缺加法/名字/比较/接收/联合接收/函数机制的实际反例；等于阈值、空清单、零次循环；多输出常量搭便车；原正确解；回到页面/重载/编辑undo/换组/提示计数和源码保留。11语、正常比例与模拟手机视口实看。小修改无需重装服务；发布前确认server tree确未改变。

实施核验：220项前端检查通过。真实页面已验证cargo.log()补加法、相等边界定位第3组、补学往返保留第8组、刷新后重新定位失败输入、成功后收起提示且可再次展开。实际下载仍是v3六域、诊断原6字段，已查看提示2次与原草稿保留，无新成绩或完成项。11语390宽无横溢出、Arabic RTL/代码LTR。下一步建议放在长提示之前；“查看这组输入”重绘后将键盘焦点交给对应输入按钮。仍未进行真实零基础学习效果实验，不能将这些检查当作学习迁移证据。
