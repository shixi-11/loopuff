核心判断

环灵需要一条让人逐渐能独立做事的学习路线。 运行示例、改对数字、通过关卡，分别只能证明相应行为；学习者还需要经历理解需求、拆分步骤、自己编写、遇错修复、换输入再检查。这是结合材料与环灵现状作出的设计判断，尚未经过学习者研究。

官方资料支持三个方向。[高] 完全没学过编程与已经会编程的人需要不同入口，Python Tutorial、Rust Book 及 Go 模块教程都明示编程经验门槛。[高] CS50P、MDN 和 Rust 项目章让小作品随着需求生长，概念有当下用途。[高] CS50P 最终项目、Rust 项目测试章节和 Go 教程把进阶延伸到独立实现、错误处理、测试与代码组织。课程结构的证据不等于采用后必然改善学习效果。

他们怎样把人带进入门

CS50P：教会运行，让一个程序不断生长

课程介绍明确接纳有或没有编程经验的人。第0课笔记从编辑器、文件、终端和运行关系讲起。问候程序先显示文字，再需要读取姓名、保存结果、显示姓名，变量因此有了用途。课程还展示少写括号会报错，以及把名字写进引号只会显示固定文字，让人看到语法错误和结果不合预期的区别。

第一次作业并非重抄原例。Indoor Voice要求转换输入大小写并保留其他内容，给出具体操作、提示和手动测试。Tip Calculator提供主程序，留下小函数待补。这些是不同支架，不能概括为所有作业都严格先填空后独立。

循环课先重复输出，再提出大量重复时怎么办，随后引入计数与循环。Coke Machine把循环、条件、状态组合成持续收款的需求，并检查不同输入结果。环灵可采用：先说清角色要做什么，再让概念解决眼前问题；阶段结束换情境检查。 一节大学课程的内容量不宜原样压进新手首屏。

MDN：先体验目标，再拆成可完成的步骤

学习区总览区分起步、核心、扩展，也区分单项技能检查与综合挑战。第一个网站从作品计划开始，逐步完成内容、样式、交互和发布，并说明文件操作等预备知识。JavaScript 章节还要求 HTML 与 CSS 基础，不能单独当作没有前置条件的课程。

第一次JavaScript实践先给可体验的猜数字目标，再把需求拆为记录回合、接收猜测、比较、提示、结束和重置等步骤，逐步实现。它明确提醒此时不要求掌握全部代码，后续会返回这些概念。故事生成器挑战提供部分起始结构和行为要求，让多项知识共同工作。

环灵可采用：先体验很小的完整任务，随后只开放正在学的部分。 先看角色遇到障碍，再改决定行动的条件；阶段结束撤掉部分结构。首次作品应足够小，避免让人面对一屏陌生代码。

Rust Book与Rustlings：项目、改错和进阶工程相互补充

Rust Book导言明确假设读者写过其他语言，并区分概念章与项目章。猜数字项目从可运行版本逐步增加输入、比较、重复、退出和无效输入处理。中间版本可以不完善，每次改动却对应具体行为，后续再系统解释细节。

Rustlings按主题组织练习，修改后重跑，提示按需查看。多数题修复已有错误，部分题要求通过测试。它训练读代码和理解诊断，不能单独证明能从空白做项目。Rust Book 也经常给完整代码，二者不能被描述为已经拥有环灵需要的完整撤提示阶梯。

进阶组织的具体例子在minigrep重构及测试章节：从责任混杂、含糊错误和难测试问题出发改善程序，用先失败的测试检查实现。高级特性章则把部分低频能力定位为特定情境的参考。

环灵可采用：进阶增加变化、缺陷和维护要求。 学习者要解释失败、局部修复并保持其他行为，再比较方案取舍。Rust 的所有权、类型和并发机制不移植为 Tolang 规则。

Python与Go官方教程：已有基础者的转换入口

Python Tutorial直接说明面向会编程、刚学 Python 的人。Go模块教程同样写明需要一些编程经验，围绕一个模块逐步加入错误、变化结果、多输入、测试和构建。Go测试一节检查正常与错误输入，还故意破坏程序，让读者观察测试失败。

环灵可采用：已有基础者先做诊断与迁移，按缺口补课。 语言对照帮助理解 Tolang 表达；消息、回复和联合接收等需要重新建立理解的部分，给真实执行与专门任务。界面写上“进阶”不能代替这条路线。

环灵的两条学习路线

以下是整体设计。零基础六步、原有课程衔接及进阶诊断与项目入口已实现；真实工具链和系统实练仍待推进。

阶段零基础者的经历已有基础者的入口能观察到的能力证据
第一次运行找到代码、运行和结果，知道编辑后要重跑，读一个简单错误可跳过操作说明，直接运行并解释指出自己改了什么及结果为何变化
控制行为在角色场景中使用输出、计算和名字，一次只解释必要概念做语法、输出诊断，补差异完成新目标，分清语言输出与游戏动作
根据状态决策观察输入，再学比较、条件、重复与终止做多输入与临界值挑战同一程序应对变化，能定位一次失败
组合行为用函数解决重复，在小场景中理解返回和消息对比函数、回复与消息的真实差异组合功能并解释数据如何到达结果
独立项目只给目标和公开案例，自己拆分、编写、补测试同一目标增加约束和变化场景交付自己的程序，说明限制并修复反例
Tolang 进阶实练准备充分后进入真实工具链与复杂语义按主题选练系统任务检查真实语义、调试、测试和组织；课程需另行实现

现有13项课程，以及预测、改写、独立编程和相关诊断，现已接到两条路线中。原有ID、草稿与进度保留。当前网页是受限入门解释器，完整Tolang系统能力不能列成已开放课程。

第一段航程的具体课程样稿

学习者的问题教学与操作随后的独立动作
我在操作什么？指明代码区、运行入口、结果区；用已有 7.log() 显示数字，解释这是一条指令指出哪个是程序，哪个是结果
改了为什么还没变？只改一个数，先预测再重跑；编辑时撤回旧结果自己完成下一次修改与运行
少写符号怎么办？展示一处有意的语法错误，说明位置、原因和修正，保留原稿找到并修复同类错误；不把环境失败算答错
为什么计算、起名字？用现有加法和名字示例解决一个具体目标，解释同一个量多次使用的用途改初始量，自己写出新的目标
角色怎样判断路况？接入已有追逐试写，观察体力与路障、写条件、看真实输出及预演用同一程序处理变化输入，解释临界值与失败
我能自己做吗？给新目标和公开案例，减少起始结构；帮助仍可主动打开自己拆步骤、编写、测试，再处理新案例

这里的重点是操作间的因果。概念名称紧跟用途出现，代码与场景承担解释；无需把所有步骤同时堆成首屏卡片，也不以速度或游戏分数替代能力证据。

课程、练习与执行怎样组织

课程层保存目标、前置建议和任务；讲解层保存最小例子、误解及帮助；练习层保存起始程序、公开输入、要求与变化场景；运行层负责执行、日志、源码位置和错误；游戏层把结果解释为角色行动；项目层检查组合行为与测试。这是对环灵的组织建议，未据此推断各站的后端架构。

作者维护题目时，让参考解通过、指定错误被识别，并接受不同正确程序。学习者进入进阶时，逐步学会自己提出测试。后者的依据包括 CS50P最终项目、Go 测试教程和 Rust 项目测试章节；在 Tolang 中的具体实现仍需设计。

证据、认识变化与局限

第一轮定位课程目录与适用对象；第二轮追读第一课、独立作业、综合挑战、项目重构及测试。主要修正是：语言入门书与编程零基础课的门槛不同；“项目先行”不要求第一次就看懂所有代码。各课程的支架不一致，本文的撤提示阶梯属于环灵的综合设计。

跨课程结构判断有多份独立官方来源，标为[高]；单页具体描述仅代表该页；环灵适配的实施范围见上一节，其余仍是建议。没有依据断言某个顺序最有效，也没有证据认定现有13课能让零基础者掌握完整Tolang。本次没有全面调查算法、完整并发及系统实战课程，它们应另作专题，不用别的语言语义填补未知。
