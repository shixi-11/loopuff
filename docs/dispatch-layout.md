# Keeping editing context during investigation

The existing two-column dispatch workspace stretches the left card to the height of the inspector. Opening a long execution record then scrolls the actual editor out of view and leaves a large empty card beside the record. This change keeps the editing context available during that comparison without reducing font size, changing browser zoom or cropping game art.

| Surface | Layout job | Transformation |
| --- | --- | --- |
| Desktop wider than 800 CSS pixels with enough height | Compare a selected value with its program, then edit and rerun | Keep the existing two columns. Within the left card, group the form, status, hint and reset controls into one editing region. That region follows page scrolling beneath the actual site header only when it fits completely. |
| Wide but short window, enlarged editor, expanded long hints | Read or edit content that exceeds the available height | Use normal document scrolling. Never trap the run button or content inside a fixed panel. |
| Tablet/mobile at 800 CSS pixels or below | Edit, run, then inspect in sequence | Preserve the single-column flow and all actions. No sticky editing region. |

The selected batch inspector and whole-program results form a single right-hand review column. Keeping the overall result below the trace in that column also leaves editing context available at the final trace record; no artificial blank padding is added. The existing batch table retains its own horizontal scroll on constrained widths.

Hint and reset disclosures stay after the form in DOM and visual order. Their closed summaries share a compact row; expanding either reveals its complete existing content. The textarea retains its font, native resize control and scroll behavior. All existing traces, game previews, batch selection, keyboard focus, state and saved work remain intact.

An optional ResizeObserver measures the editing region and current header. Page resize, editor resize, translations and disclosure expansion update whether it fits; an unmounted or replaced view must disconnect its observer and resize listener. Browsers without this enhancement retain ordinary scrolling. When the first edit removes a stale report and shortens the right column, a focused desktop editor that fits the viewport is revealed if that change clips it. This does not change focus, caret or code, and does not impose scrolling on a mobile or oversized editor. Layout measurements are transient and never enter progress data.

Acceptance: at 100% browser zoom on a desktop viewport, selecting the first and last execution records must leave the source editor and run button visible alongside the record. The sticky region must clear the actual header, stay inside its card, and disable itself when too tall. Verify long text/RTL, mobile, resizing, editing, rerunning, navigation and observer cleanup.
