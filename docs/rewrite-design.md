# 从改数值到独立编程

问题：13课的数字填空成功后立即清空程序，缺少整段改写；入门页也直接跳空白任务。

决定：在现有课程内加入 rewrite 阶段。初次以刚刚实际运行的程序为起点，显示一个新的目标；允许编辑整段程序，以真实执行和输出的数据贡献判定。随后进入原有独立任务。熟悉的人仍可直接独立作答；通过改写不新增成绩、完成项或掌握声明。独立完成后能进入相关多输入诊断。

持久化：沿用 course 和 lessonWork，每课可选 rewriteDraft 字符串（4096字符上限），missing 表示从未进入，空串表示主动删空。切课显式清除不存在的字段，不能借用前课草稿。draft/assessedSource 继续只代表原有工作；从独立页返回改写、刷新、切语言或合并不得覆盖独立程序及其提交。数字填空成功仍按原行为清空 draft，然后以本次实际程序初始化改写。

格式保持 v3 六域，无新表。旧档可读；合并时缺少改写草稿的一方继承存在方的可选字段，再比较整课快照。两方都有不相同的改写，保持整课明确选择；预览同时显示两种程序。服务在 CAS 后拒绝遗漏已存改写的旧客户端写入（SAVE_VERSION），防止旧页悄悄擦除。

界面：复用实际执行现场；改写编辑器独立于原 program-editor。运行、错误、提示、修改后失效、保存失败均有反馈。通过后继续按钮只认可当前源码的重新检验。提示不会插入答案，独立草稿不会被例程替换。比较页继续直接独立；零基础页提供继续改写和直接独立两条入口。

非目标：不改语言、调度器、评分、13个任务ID、小游戏规则、主导航、美术、现有独立题及旧存档意义。此阶段不以用户效果未测的练习通过率声称已掌握语言。

审查补充：改写逐条检查输出的数据贡献；counter首值无需来自递增，但必须来自名字，后续加法必须贡献数据。函数课需要两次不同输入的实际调用复用同一函数，不能靠无关调用凑数。为此运行器增加显式可选 provenance 观察（默认关闭），只携带返回值经过的 invocation ID、函数身份和有界参数快照；值经算式、列表元素与通道继续携带，控制条件不变成数据来源。不改变默认结果字段、执行次序、步数或语言规则；此元数据不入存档。其他课的固定中间输入只是示例，目标按真实输出和概念判断，允许合理异解。

验证：全部13种改写的不同合理解、硬编码反例、错误/等待反馈；旧档/missing/空串/切课、独立稿保护、整课冲突和旧writer；真实浏览器填空→改写→独立→诊断、刷新/语言/提示/备份；新增例程与已固定官方原生执行对照。预期：新增可选字段能沿用原恢复/合并架构，中等置信；若需新冲突粒度先回到本提案裁决，不另建进度域。

2026-11-03 实施检查：215项前端检查与19项实际账号服务测试通过。15份新程序与固定原生执行器相等；运行器默认观察、trace和开启后剥除来源字段的差异对照通过。真实浏览器已跑13课改写、comparison完整预测→解释→填空→改写、signal独立提交往返与诊断入口、11语390宽无溢出/代码LTR、实际下载和冲突恢复。恢复空白改写后独立12.log()、原100分/1次尝试仍保留。三镜的遗漏保护、伪数据贡献、调用凑数和共享列表指数展开反例均修复并定点关闭。仍未做零基础玩家盲测，不声称这项实现已证明学习迁移。
